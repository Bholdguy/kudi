# Kudi

Passkey-based freelancer invoicing: one passkey derives a receiving address per client; clients pay AUSD on Monad testnet. Live at https://kudi-bholdguy.vercel.app, code at https://github.com/Bholdguy/kudi. Built for Monad Metropolis (Consumer Products & Payments). The original PRD was removed at submission; this file carries what still matters from it.

## Stack
Next.js App Router, TypeScript, Tailwind, viem, `@category-labs/mera`, `@scure/bip32`, `@scure/bip39`, vitest. No wagmi (see decisions log). Hosting: Vercel (`npx vercel deploy --prod --yes`).

## Config rules
- Addresses, chain ID, RPC URLs, explorer URL and every tunable number live only in `lib/config.ts` (env overrides: `NEXT_PUBLIC_RPC_URL`, `NEXT_PUBLIC_RPC_URL_FALLBACK`, `NEXT_PUBLIC_PASSKEY_RP_ID`). `NEXT_PUBLIC_*` values are inlined at build time.
- Token decimals are read from the contract, never hardcoded. All token math is bigint.
- No mock data, no `console.log`, no TODOs. Never commit `.env` or keys.
- Freelancer-side copy never says "wallet", "gas", "seed", "private key" or "mnemonic". The client's pay page may say "wallet" and "gas".
- Nothing loads from a third-party host: no external fonts, images or component libraries.

## Non-goals (original scope)
- No automatic sweeps. Freelancer-initiated sends on Arc only, one passkey prompt per send, private keys never stored.
- No fiat on/off-ramp.
- No backend, database or server accounts.
- No credit, subscriptions or recurring billing.
- No mainnet.
- No FX rates or live price API.
- No email, SMS or push notifications.
- No multi-token support (AUSD only).
- No native mobile app.
- No AI features.
- No smart contracts written by us.

## Commands
`npm run dev`, `npm test` (116 unit tests), `npm run lint`, `npm run build`. After deleting a route, remove `.next` before `tsc`, because `LayoutProps` and route types are generated by `next build`.

## Decisions log
- Fallback RPC comes only from `NEXT_PUBLIC_RPC_URL_FALLBACK`; if empty or equal to the primary, run on the primary alone. Production uses `https://rpc-testnet.monadinfra.com` (Monad Foundation, 20 rps). Official MON faucet: https://faucet.monad.xyz.
- Explorer is `https://testnet.monadscan.com` (viem's `monadTestnet` lists a different one; config overrides it). AUSD testnet `decimals()` = 6.
- Dropped `next/font/google` (needs network at dev time, adds an external host). Added `lib/client.ts` (shared viem public client). tsconfig target is ES2020 for BigInt literals.
- Scaffolded in a lowercase scratch folder because npm rejects the capitalised folder name `Kudi`; package name is `kudi`.
- Derivation follows Mera's demo: PRF output, BIP-39 entropy, BIP-44 `m/44'/60'/0'/0/{i}`. Mera has no BIP-44 helper; `lib/passkey.ts` owns it. Mera has no "cancelled" error code, so `PASSKEY_OPERATION_FAILED` maps to the "cancelled" copy. Errors are matched by `MeraError` code, never by message text.
- `accountXpub` (xpub at `m/44'/60'/0'/0`) is stored in `kudi:v1` on purpose. It is public data and lets client addresses derive with no passkey prompt. Private material (PRF output, seed, HD nodes) is zeroed after use; the transient mnemonic string cannot be zeroed in JS.
- KUDI-17 (signed invoices) DROPPED by the owner: signing needs a client-address private key, and with the xpub stored in the browser one exposed child key reveals the whole account's keys. The `sig` link parameter is unused.
- Signed-in state is a `sessionStorage` flag: closing the tab means signing in again. Account data stays in localStorage, with an in-memory fallback for private windows. Landing: with a saved account, "Sign in" is primary and "Create a new account" is a small link. The passkey `rpId` is the production hostname, `localhost` in dev.
- Client addresses come from `addressAt(accountXpub, index)`; the UI shows the derived address, never the stored copy. Indexes start at 1 (0 is home). Duplicate client names allowed. Total received sums client addresses only.
- Balances: one batched (multicall3) read every 5 s, paused while the tab is hidden; last values kept on failure. Amounts display with 2 decimals, truncated (`lib/amount.ts`).
- AUSD faucet: proxy `0xd236c18D274E54FAccC3dd9DDA4b27965a73ee6C`, implementation `0xba804DF5c476E8EaeF87BF8085F295300ccE2a49` (verified, AgoraFaucet). `requestFunds(address _receiver)` sends 10,000 AUSD to any receiver; receiver cap 100,000 AUSD; 60 s `maxDripFrequency` with one global `lastDripTimestamp` (read as a shared cooldown; source not read).
- Stored invoices carry `createdAt` and `paidAt`; clients carry a `scan: {through, transfers}` cache. Invoice id is `inv_` plus 6 characters from a look-alike-free alphabet. Amounts are typed as digits with at most 2 decimals, 0.01 to 1,000,000. A new invoice records the live block number; if the read fails, nothing is created. The pay link is `/pay?v=1&to&amt&inv&n&c&m&b`, and any invalid field makes it a broken link.
- DEVIATION FROM THE ORIGINAL STACK (owner decision, for time and risk): no wagmi and no react-query. The pay page uses viem only: `window.ethereum` with `createWalletClient(custom(provider))`, `requestAddresses`, `switchChain`, and `addChain` on error 4902 (`lib/wallet.ts`). Wallet errors are matched by code (4001, 4902, -32002), walking the `cause` chain. A sent-but-unconfirmed payment offers only "Check again", never a retry.
- Gas is viem's `estimateContractGas` with no padding, because Monad charges the declared limit. The owner's real payment used a 55,862 gas limit and 55,862 gas used.
- Both RPCs reject `eth_getLogs` ranges over 101 blocks. `lib/scanPlan.ts` splits any gap into windows of `config.logMaxBlocks` (100); the same planner serves the first catch-up and every live poll, so a sleeping phone or hidden tab is covered by more windows, never one big request. Capped at 200 windows per pass. Measured: 123 windows (12,215 blocks) in 11.8 s.
- Matching (`lib/reconcile.ts`) recomputes statuses from scratch per client from cached transfers (idempotent): chain order by (block, logIndex), only transfers at or after the invoice's block; an exact completion of the oldest open invoice wins, otherwise the oldest open invoice takes it; short payments add up (30 then 20 settles 50); extra shows as "+X AUSD extra"; a transfer with no open invoice matches nothing. Scan progress lives in memory between passes and is saved when something changes or every 600 blocks; creating an invoice rewinds the saved mark.
- Full-screen "Paid" appears only for payments that land after the first full pass reached the head; one found during catch-up or on reload just shows Paid in the list. Elapsed time is block timestamp minus `createdAt`, clamped at zero. Faucet drips after an invoice exists count as ordinary transfers (E12): fund test accounts before creating invoices.
- E15: "Network is busy, retrying..." appears only after 2 failed attempts in a row (`lib/retry.ts`). E16 recovery (`lib/recovery.ts`): signing in with no saved clients probes client indexes 1 to 20 in one batched AUSD read and rebuilds clients up to the highest funded index as "Client N" (tested with mocked chain reads only). KUDI-18 (`lib/activity.ts`): last 10 incoming transfers, from the cached transfers of clients that have invoices.
- Design (followed the frontend-design skill): adire-indigo `#232d7a` for trust, marigold `#f4b22b` only for the brand coin and the Paid celebration, paper `#f7f6fb`, palm `#0b6b4a` for Paid, clay `#b3261e` for errors; tokens in `app/globals.css`. Display face Bricolage Grotesque Variable, self-hosted via `@fontsource-variable/bricolage-grotesque` (41 KB latin); body uses the system font. Brand mark is an inline SVG K with a coin (`components/BrandMark.tsx`, `app/icon.svg`). Boldness is spent on the Paid moment (count-up from 0.00 to the exact amount, confetti, vibration on Android; reduced motion gets the finished state). It renders only once decimals are known and shows real stored names and amounts.
- Liquid glass (git tag `pre-glass` marks the commit before it) is used in exactly two places: the Paid celebration's centre panel and the pay page invoice card, with `-webkit-backdrop-filter`, blurred indigo and marigold blobs behind, and a solid fallback where unsupported. The one page-load motion is a CSS-only staggered rise (`.stagger`), off under reduced motion; its fill mode is `backwards` so no transform is left to trap the fixed Paid screen.
- Do NOT lazy-load `lib/passkey` on the landing page: iOS Safari needs the passkey prompt straight after a tap, and awaiting a code chunk in between could lose that (tried, reverted).
- Measured with Lighthouse (live, Moto G Power emulation, simulated 4G): pay page first paint 1.1 s; landing first paint 1.1, 1.3, 1.9, 2.3 and 3.9 s across five runs, so NFR-04 (under 1.5 s) is inconclusive on this network; accessibility 100 on both. A 375 px script audit of landing, dashboard, pay, 404 and the Paid screen found no horizontal overflow, no contrast failures and every button at least 44 px tall.
- The agent never sends or confirms a payment; real payments were made by the owner from MetaMask. Wallet-less UI states were checked with throwaway page hooks that reject every send; they are not part of the shipped code.
- checklist.design was audited through its public JSON (`/api/checklists/by-slug`) because its pages stay on "Loading…" in the in-app browser. Skipped on purpose: social sign-in, customer counts, testimonials, billing, notifications (non-goals, or would need fake data).
- Sends were a non-goal until real USDC on Arc mainnet made an exit necessary: without Send, a freelancer who is paid real dollars has no way to move them out of Kudi. Scope is Arc only and freelancer-initiated only (no sweeps, no automation). Each send derives the child private key only after the user taps Confirm, uses it once, and wipes it in a finally block. Keys never sit in React state, storage, logs or errors. Monad has no Send.
